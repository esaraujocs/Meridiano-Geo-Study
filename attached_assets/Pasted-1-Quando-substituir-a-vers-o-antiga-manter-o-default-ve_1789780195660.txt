1. Quando substituir a versão antiga → manter o default (vertical slice de Mapa primeiro). É exatamente a lógica que já conversamos: valida a peça de maior risco isolada antes de comprometer todo o resto. Não mudaria.

2. Distribuição inicial → manter o default (URL + PWA, lojas depois). Reduz escopo/atrito (sem review de loja) enquanto ainda estão validando se o rebuild vale a pena. Não mudaria.

3. Mapa offline → aqui eu não bateria o martelo ainda. "Mapas regionais baixáveis" é a opção mais robusta no papel, mas é bastante complexidade nova (gerenciador de download, quota de storage, versionamento por região) — e vocês só vão saber se isso é necessário depois que a Fase 0 medir o tamanho real do PMTiles pro mundo inteiro em detalhe suficiente pra ilha pequena. Vale registrar como intenção, mas eu comentaria: "decisão final condicionada ao tamanho medido na Fase 0 — se o tileset mundial completo em detalhe usável couber num download inicial razoável, prefiro mapa mundial completo offline a construir um sistema de download regional que pode nem ser necessário." Também vale lembrar: o app atual já depende de CDN pra rodar (d3/topojson via internet) — "offline de verdade" nunca existiu, então não é uma regressão se a v1 do rebuild exigir internet pro mapa enquanto o resto funciona offline.

4. Liberação de modos → manter o default (moeda + requisito simples de aprendizagem). É o que evita os dois extremos ruins: moeda pura deixa comprar acesso sem estar pronto; maestria pura mata a progressão que vocês pediram. Não mudaria.

5. Jogadores atuais → manter o default (saldo + desbloqueios retroativos). Já é o que ficou acertado no plano original (ninguém perde progresso, ninguém é forçado a re-desbloquear o que já domina). Não mudaria. Vale notar que hoje isso é baixo risco na prática — o "jogador atual" é basicamente você mesmo testando pelo celular, então o custo de acertar essa política agora é baixo.

6. Direção visual → essa é genuinamente sua, não técnica. Um dado pra pesar: a versão atual já usa um fundo claro tipo "papel" (--paper, off-white). "Atlas claro/mineral" reaproveita esse território visual (rebrand mais suave); "cartografia escura/noturna" é uma virada mais forte, que combina melhor com "rebrand de verdade" mas parte do zero. "Explorar variações antes de escolher" só vale o custo se vocês tiverem tempo pra gastar em protótipo visual antes de validar o mapa — eu não gastaria esse tempo agora, dado que a prioridade nº1 declarada é a substância técnica, não a estética. Se for decidir sem protótipo, eu iria de escura/noturna pra marcar visualmente que é um produto novo, mas é factível defender qualquer uma.

Resumindo: aceitar os defaults em 1, 2, 4, 5; comentar a ressalva em 3 (condicionar ao dado real da Fase 0); e decidir 6 por gosto seu, sem gastar tempo de protótipo nisso agora.
